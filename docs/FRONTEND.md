# Устройство React-фронтенда

Фронтенд использует React, TypeScript, React Router и Vite. После рефакторинга маршруты, CSS-классы, тексты интерфейса и HTTP-контракт сохранены. `App.tsx` сокращён с 2034 до 42 строк и отвечает за сборку провайдера, каркаса и маршрутов.

## Структура `frontend/src`

| Каталог | Что находится внутри |
|---|---|
| `app/` | `AppProvider`: анонимная/служебная сессия, разделы, уведомления и обновление данных |
| `layouts/` | Общий каркас: боковая навигация, шапка, подвал, бренд и диалог завершения сессии |
| `api/` | DTO в `types.ts`; fetch-клиент, `ApiError` и параметры записи в `client.ts` |
| `components/` | Переиспользуемые сообщения состояния, модальные окна, пагинация, счётчик символов и значок раздела |
| `features/feed/` | Лента, поиск и фильтры |
| `features/topics/` | Создание/чтение темы, карточки постов, ответы, жалобы, удаление и `usePublication` |
| `features/staff/` | Служебный вход и шапка команды |
| `features/moderation/` | Очередь жалоб, решения и журнал |
| `features/admin/` | Разделы и служебные учётные записи |
| `features/info/` | Правила и описание анонимности |
| `hooks/` | Загрузка данных, черновики и состояние асинхронных действий |
| `lib/` | Форматирование дат/счётчиков, сообщения ошибок и ключи повторной отправки |
| `styles/` | Базовые правила, каркас, элементы управления, страницы, адаптивность и завершающие переопределения |

Импорты идут от страницы к её компонентам и общим модулям. Общие компоненты не зависят от страниц. Новые зависимости для рефакторинга не добавлялись.

Служебный вход доступен по прямому маршруту `/login`; публичный интерфейс не содержит ссылок на него. Пункт «Модерация» появляется в навигации только после служебного входа. Проверки ролей и прав на сервере сохранены.

## Состояние и запросы

- `AppProvider` хранит общее состояние форума. Поля форм, открытые диалоги и выбранные вкладки остаются локальными состояниями страниц.
- `useLoad(path, version)` отменяет запрос при изменении адреса или размонтировании; результат предыдущего адреса не отображается в новой выдаче. `null` отключает загрузку: модерация запрашивает только данные активной вкладки.
- `useAsyncAction` предоставляет `busy`, `error` и `run`. Он очищает предыдущую ошибку и блокирует одновременные запуски одного действия; успешное действие, навигация и уведомления определяются вызывающей формой.
- `usePublication` используется темами и ответами. Одинаковая полезная нагрузка получает тот же `Idempotency-Key` до подтверждённого успеха. Ключ переживает перезагрузку вкладки в `sessionStorage`; после успеха удаляется.
- `useDraft` синхронно сохраняет ввод в `sessionStorage`. Существующие ключи `forum:new`, `forum:reply:<id>` и `forum:submission:<name>` не менялись. Черновик очищается после успешной публикации.
- Страница темы имеет React `key` по pathname, поэтому состояние диалогов и форм разных тем не смешивается.

## Стили

`styles.css` — точка входа с упорядоченными `@import`. Разделение сохраняет все исходные CSS-правила и их порядок; responsive-правила и переопределения подключаются последними. CSS остаётся глобальным, поэтому имена классов и порядок импорта являются частью существующего оформления.

## Проверка

```sh
cd frontend
npm run build
npm run format:check
cd ..
make e2e
```

10 сценариев Chromium проверяют публикации, потерю ответа при создании темы и ответа, удаление, модерацию, архивирование разделов, текстовый вывод пользовательского HTML, размеры 360/768/1440 px, мобильное меню, изоляцию черновиков и загрузку вкладок команды. Общие шаги входа и создания темы находятся в `frontend/tests/helpers/forum.ts`.

`make e2e` использует отдельную БД `forum_e2e_test` и временный сервер на 18080; запущенный локальный сервер на 8080 не перезапускается. Фактические результаты записаны в [TESTING.md](TESTING.md).
