# Без имени — анонимный интернет-форум

Рабочий учебный проект по четырём отчётам СИПИ: **Go + React/TypeScript + PostgreSQL**. База данных запускается в **Podman**, Docker и Compose не нужны.

## Быстрый запуск на этом компьютере

Проект находится в `/Users/volentirs/doc/forum`. Зависимости установлены, локальная БД и первоначальные данные подготовлены.

```bash
cd /Users/volentirs/doc/forum
make start
```

Откройте **http://localhost:8080**. Это собранный React, который отдаёт сервер Go. База остаётся в Podman.

Служебный вход: **http://localhost:8080/login**. Локальный логин и случайный пароль находятся в **[.run/local-access.txt](.run/local-access.txt)**. Файл имеет доступ только для владельца и исключён из Git. Общего пароля по умолчанию в коде нет.

Остановить сервер: `make stop`. Остановить БД без удаления данных: `make db-stop`. Запуск не удаляет данные. Для автоматического старта после перезагрузки компьютера сначала требуется работающая Podman machine.

## Установка с нуля

Нужны Go 1.24+, Node.js 22.12+ (или 24 LTS), npm, Podman, OpenSSL, curl, make. Для копий — Python 3. На macOS Podman работает через виртуальную машину. Скрипт `db-up` запускает существующую машину, а при её отсутствии создаёт стандартную.

```bash
./scripts/setup.sh       # зависимости + .env со случайными секретами
make db-up              # PostgreSQL 17 в Podman, 127.0.0.1:55432
make migrate            # транзакционные SQL-миграции
make seed               # 5 разделов и 5 демонстрационных обсуждений
./scripts/local-admin.sh # создать локального admin со случайным паролем
make start              # http://localhost:8080
```

`seed` работает только при отсутствии разделов; существующий форум не перезаписывается. Демонстрационные сообщения не выдают себя за реальную активность пользователей. Названия контейнера и тома: `forum-postgres`, `forum-postgres-data`.

Альтернатива для создания служебной учётной записи: `make admin`. Логин, пароль и роль запрашиваются в терминале, пароль не отображается. Добавлять участников также можно через **Управление → Команда**.

## Разработка

Остановите собранный сервер (`make stop`), затем:

```bash
make dev
```

React/Vite: **http://localhost:5173**, Go: `127.0.0.1:8080`. Vite проксирует `/api` к Go, поэтому браузер работает с одним origin. `Ctrl+C` завершает серверы разработки. БД продолжает работать.

Можно запускать по отдельности в двух терминалах: `make backend` и `make frontend`. `.env` загружается скриптами автоматически. Не запускайте `make start` и `make dev` одновременно: они используют один порт API.

## Что реализовано

| Требование | Реализация |
|---|---|
| FR-01, FR-02 | Разделы, лента, стабильная пагинация по 20 записей, чтение тем |
| FR-03, FR-04 | Создание темы и первого сообщения одной транзакцией, ответы с нумерацией |
| FR-05 | Удаление своих сообщений с проверкой владельца и стиранием текста |
| FR-06 | Полнотекстовый поиск PostgreSQL с русской морфологией; фильтр раздела |
| FR-07 | Жалобы: спам, оскорбления, личные данные, другое; защита от открытых дублей |
| FR-08, FR-09 | Очередь жалоб, скрытие/отклонение с причиной, открытие/закрытие тем, журнал |
| FR-10 | Тема раз в 60 с, ответ раз в 10 с, 3 жалобы/мин; HTTP 429 + Retry-After |
| FR-11 | 256-битные сессии на 30 дней, хранение хеша токена, отзыв при выходе |
| FR-12 | Создание/изменение/архивирование разделов и управление служебными ролями |

Дополнительно: отдельные служебные сессии на 12 часов, пароли Argon2id (64 MiB, t=3, p=2), защита Origin/CSRF, параметризованный SQL, только текстовый пользовательский контент, локальные черновики вкладки и идемпотентные публикации на 24 часа. Скрытый текст не попадает в публичные ответы и поиск. Завершение анонимной сессии не завершает служебную, и наоборот.

Чтение не создаёт анонимную сессию. Она появляется при первой записи. Автор определяется только действующей сессией текущего браузера. При смене браузера или очистке cookie права на прежние сообщения теряются. Никаких публичных идентификаторов авторов нет; сервис сохраняет внутренние связи до удаления истёкшей/отозванной сессии (ежечасная очистка).

Архивный раздел запрещает новые темы. Возможность отвечать регулируется состоянием отдельной темы, как предусмотрено FR-12. Закрытая тема доступна для чтения.

## Проверки

```bash
make test         # Go unit tests + go vet + TypeScript + production build React
make integration  # PostgreSQL forum_test, тесты транзакций/прав/лимитов и -race
# Один раз при отсутствии браузера:
cd frontend && npx playwright install chromium && cd ..
make e2e          # отдельная forum_e2e_test и сервер localhost:18080
```

Интеграционные тесты очищают **только** `forum_test`; имя тестовой БД обязательно заканчивается на `_test`. Браузерные проверки создают данные в `forum_e2e_test`, рабочая БД `forum` не меняется. Тестовые базы используют тот же контейнер. HTML-отчёт Playwright: `frontend/playwright-report/index.html`.

Проверены публикация, ответы, удаление, жалоба и решение, роли, архив, потеря ответа сервера с повтором без дубля, инъекции, выдача приватных полей, пагинация и размеры 360/768/1440 px. Фактические результаты и ограничения — [docs/TESTING.md](docs/TESTING.md).

Нагрузочные цели из отчётов (100 пользователей, 15 минут), месячная доступность и RPO/RTO — показатели для отдельной приёмки на согласованном стенде. Успешная локальная сборка не подтверждает эти значения. Сценарий k6 находится в `tests/load.js`, синтетический набор 10 тыс. тем / 50 тыс. сообщений — в `tests/load-fixture.sql`. Применяйте его после миграций только к отдельной БД с суффиксом `_load_test`. На отдельном стенде задайте `NETWORK_WRITE_LIMIT=1000` и `NETWORK_SESSION_LIMIT=200`, если генератор имитирует всех пользователей с одного IP; иначе штатная защита ограничит сам генератор. Рабочие значения при этом не изменяются.

## Конфигурация

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Подключение Go к PostgreSQL |
| `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` | Первоначальная настройка контейнера |
| `POSTGRES_PORT` | Порт PostgreSQL на loopback, по умолчанию 55432 |
| `POSTGRES_CONTAINER` | Имя контейнера, по умолчанию forum-postgres |
| `SESSION_SECRET` | Случайный ключ CSRF/HMAC, не менее 32 символов |
| `APP_ORIGIN` | Точный origin, без пути и завершающего `/` |
| `API_ADDR` | Адрес Go; по умолчанию 127.0.0.1:8080 |
| `COOKIE_SECURE` | `false` только для локального HTTP; `true` для HTTPS |
| `NETWORK_WRITE_LIMIT`, `NETWORK_SESSION_LIMIT` | Сетевые лимиты записи/создания сессий в минуту: 120/20; изменение для отдельного нагрузочного стенда |
| `STATIC_DIR` | Путь к сборке React; `start.sh` задаёт автоматически |

`.env.example` не содержит рабочих секретов. `setup.sh` создаёт `.env` с правами 600. Пароль в `.env` должен совпадать с паролем уже созданной PostgreSQL: изменение переменной не меняет пароль внутри существующего тома.

`make start` предназначен для локального показа: он задаёт `APP_ORIGIN=http://localhost:8080`. Для внешней публикации соберите проект (`make build`), поставьте HTTPS reverse proxy перед Go и задайте `APP_ORIGIN=https://ваш-домен`, `COOKIE_SECURE=true`, `STATIC_DIR=/путь/frontend/dist`, затем запустите `backend/bin/forum`. Backend отказывает в небезопасной конфигурации cookie для внешнего домена. Go слушает loopback; доступ к нему снаружи выполняется через HTTPS proxy. Отдельно настройте HTTPS, резервное копирование и мониторинг до такой публикации.

Сетевые лимиты используют HMAC адреса соединения в памяти, не записывая IP в журнал. Заголовки `X-Forwarded-For` не считаются доверенными: за reverse proxy пользователи разделяют сетевой лимит. Для масштабирования настройте доверенные прокси и общий счётчик отдельно; локальный проект работает одним экземпляром Go.

## Резервное копирование

```bash
make backup
./scripts/restore-check.sh backups/forum-YYYYMMDDTHHMMSSZ.dump
```

Копии создаются `pg_dump -Fc`, сохраняются с правами владельца в `backups/`, остаются последние семь успешных файлов. Восстановление создаёт **новую** БД `forum_restore_<время>`, не затрагивая рабочую, и выводит контрольные количества записей. Автоматическое расписание не установлено: для эксплуатации запускайте `backup.sh` ежедневно через планировщик ОС и храните копии также вне диска с базой. Удаление тома Podman удалит рабочую БД — обычные команды проекта том не удаляют.

## Структура

```text
backend/
  cmd/api/                 CLI: serve, migrate, seed, create-staff
  internal/forum/          HTTP-слой, транзакции публикаций/модерации, сессии, тесты
  migrations/              встроенные версионированные SQL-миграции
frontend/
  src/                     React, типы API, стили, формы и черновики
 tests/                   Playwright сценарии
scripts/                   Podman, запуск, тесты, копирование/восстановление
docs/openapi.json         контракт API OpenAPI 3.0.3
docs/TESTING.md            фактические проверки и оставшаяся приёмка
tests/load.js             нагрузочный сценарий k6
```

Устройство бэкенда и границы транзакций: [docs/BACKEND.md](docs/BACKEND.md).

API: [docs/openapi.json](docs/openapi.json). Запросы записи требуют `Origin`. Анонимная сессия создаётся `POST /api/v1/sessions`, служебная — `POST /api/v1/staff/session`. Оба ответа содержат соответствующий `csrf_token`; в остальных изменяющих запросах он передаётся как `X-CSRF-Token`. Публикации также требуют `Idempotency-Key`. Формат ошибки: `code`, `message`, `request_id`; `Retry-After` приходит заголовком при лимите.
